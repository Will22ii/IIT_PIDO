## 1. 등식은 두 종류다. eps의 유무가 이를 가른다.

이 구분이 이 문서 전체의 뼈대다. 등식을 한 종류로 다루면 처리 방식을 정할 수 없다.

### Type 1 — 공차가 있는 목표값

고유진동수 50Hz, 출력 토크 목표치, 열팽창 매칭 같은 **튜닝 문제**.

- **eps가 물리적 의미를 가진다.** 규격이나 공차표에서 나오는 값이다.
- 엔지니어가 "50Hz여야 한다"고 말해도 실제 요구는 `49.5 ~ 50.5`다.
  제조 공차와 재료 편차 때문에 정확히는 어차피 안 나온다.
- **즉 애초에 밴드다.** `|y - L| <= eps`를 rejection으로 다루면 된다.

### Type 2 — 구조적 등식

기하 폐합 `l1 + l2 = l3 + l4`, 비율 고정 `x1 / x2 = 3`, 질량 보존 `sum(rho_i * V_i) = M`.

- **eps에 물리적 의미가 없다.** 위반하면 조립이 안 되거나 말이 안 된다.
- 만족해야 할 조건이 아니라 **설계공간의 정의**다. 자유도를 하나 없앤다.
- **밴드로 다루면 안 된다.** eps가 임의값이고, 밴드 안을 헤맬 이유가 없다.
  등식이 정의하는 면 위에만 있으면 된다.

### 판별 방법 — 유저 입력의 eps 유무

```
{"type": "==", "limit": 50.0, "eps": 0.5}    -> Type 1. 밴드 rejection
{"type": "==", "limit": 0.0}                  -> Type 2. 투영
```

유저는 아무것도 더 배울 필요가 없다. **공차가 있으면 적고, 없으면 안 적는다.**
그것이 곧 의도 표현이 된다.

### 현행 코드의 문제 — 자동 eps가 Type 2를 Type 1인 척 처리한다

```python
# constraint_filter.py:151-157
scale = max(abs(limit), 1.0)          # limit이 0이면 근거 없이 1.0
eps   = max(scale * 0.02, 1e-6)
```

eps가 없으면 `limit`의 2%를 몰래 채워 넣는다. 그래서 `l1+l2 = l3+l4` 같은 Type 2가
"±2% 밴드"가 되어 rejection으로 헤매다 실패한다.

게다가 이 계산은 **`limit` 값만 보고 변수 범위를 보지 않는다.** `limit=0`이면
스케일 정보가 아예 없어서 `1.0`으로 떨어진다:

| 제약 | 변수 범위 | 자동 eps | 실제 의미 |
|---|---|---|---|
| `x1 + x2 == 0` | `[0, 0.001]` | 0.02 | 최댓값 0.002 < 0.02 -> **모든 점이 통과.** 제약이 없는 것과 같음 |
| `x1 == 0` | `[-1e6, 1e6]` | 0.02 | 통과율 `1e-8` -> **아무것도 못 뽑음** |

같은 문법인데 변수 스케일에 따라 무제약이 되기도 불가능해지기도 한다.
코드는 변수 스케일을 모른다. **공차는 유저만 아는 도메인 지식이므로 유저가 정해야 한다.**

따라서 **자동 eps 계산(`eps_ratio`/`eps_min`)은 제거 대상**이다.

## 1.1 4칸 처리 방식

| | Type 1 (eps 있음) | Type 2 (eps 없음) |
|---|---|---|
| **pre** | 밴드 rejection — **현행으로 동작** | **투영** (이 문서 3절~) |
| **post** | CAE 후 라벨링 — **현행으로 동작** | **정확 일치로 라벨링 + feasible 부족 시 경고** |

**투영이 필요한 칸은 `pre + Type 2` 하나다.**

### post Type 2는 존재하지만 투영이 필요 없다

post Type 2는 **이산 출력**에서 실재한다.

```
n_modes == 3            (주파수 이하 모드 개수)
n_contact_pairs == 2    (접촉 쌍 개수)
converged == 1          (수렴 여부)
```

정확한 등식이고 공차라는 개념이 없다. 3이거나 3이 아니거나다. 명백한 Type 2다.

**그런데 이것이 병리적이지 않다. 이산 출력의 역상은 얇은 면이 아니기 때문이다.**
`n_modes == 3`을 만족하는 설계점들의 집합은 **부피를 가진 영역**이다.
"모드가 3개 나오는 설계"가 설계공간의 어떤 덩어리를 차지한다. 측도 0이 아니다.

| | 역상의 성질 | rejection 통과율 | 투영 필요? |
|---|---|---|---|
| 연속 출력 + 정확 등식 | 측도 0 면 | ~0 | 원리적으로 불가 (아래) |
| **이산 출력 + 정확 등식** | **부피 있는 영역** | **정상** | **불필요** |

반면 **연속 출력에 대한 정확 등식은 의미가 없다.** `stress == 5000`을 무한 정밀도로
요구하는 것은 물리적으로도(제조/측정 정밀도) 수치적으로도(메시, 수렴 판정, 부동소수점)
성립하지 않는다. 유저의 정식화 실수다.

### 그래서 post Type 2는 "정확 일치 + 경고"로 처리한다

eps가 없으면 **정확 일치**(수치 오차 흡수용 극소 eps)로 라벨링한다.

- **이산 출력이면** 정상 동작한다. 원하는 대로다
- **연속 출력이면** feasible이 0에 수렴한다. 그때 경고한다

```
[DOE][PostConstraint][WARN]
  'stress_target' feasible 0/90.
  연속 출력에 정확 등식은 만족될 수 없습니다. eps를 명시하십시오.
```

**코드가 이산/연속을 판별할 필요가 없다.** 관측된 feasible 개수만 보면 된다.
이산이면 통과하고, 연속이면 0이 나와 경고가 뜬다.

그리고 이 경고는 "post feasible 개수가 Modeler 요구치(10행)를 밑돌면 알린다"와 **같은 장치**다.
등식/부등식 구분 없이 하나로 처리된다. 빡센 post 부등식(`sigma <= 0.001`)도 같은 병을
가지므로 함께 잡힌다.

### post에 투영을 쓸 수 없는 이유 (Type 1이어도)

투영은 `∇h`를 구하려고 `h`를 반복 평가하는데, post의 `h`는 한 번 평가에 CAE 한 번이다.
점 하나 투영에 CAE `5(p+1)` ~ 50회가 필요하므로 전체 예산이 90회인 문제에서 성립하지 않는다.
구현 한계가 아니라 구조적 사실이다 — 샘플링 전에 평가할 수 없는 것으로 샘플링을 조종할 수 없다.

## 2. 왜 Type 2를 rejection으로 풀면 안 되는가

부등식의 feasible 영역은 **양의 부피**를 가진다. `sigma <= 5000`은 공간의 상당 부분을 남기므로
무작위로 던져도 잘 맞는다. 현재 cantilever가 이 방식으로 정상 동작한다.

등식은 다르다. feasible 집합이 **측도 0인 매니폴드**를 밴드로 두껍게 한 얇은 껍질이라
수율이 등식 개수 `m`에 대해 지수적으로 붕괴한다.

| m | 수율 (밴드 폭이 범위의 2%일 때) | 필요 후보 배수 |
|---|---|---|
| 1 | ~2% | 50배 |
| 2 | ~0.04% | 2,500배 |
| 3 | ~0.0008% | 125,000배 |

**Type 1은 이 표가 낙관적이다.** 유저가 정한 현실적 공차(예: 50Hz +-0.5 = 1%)는
자동 eps와 비슷하거나 넓은 경우가 많고, 무엇보다 **유저가 스스로 선택한 어려움**이다.
좁게 잡아 샘플이 안 모이면 그건 `sigma <= 0.001` 같은 빡센 부등식과 같은 상황이며
특별 취급할 이유가 없다.

**Type 2는 이 표를 적용하는 것 자체가 틀렸다.** 밴드 폭이 임의값이므로 수율도 임의값이다.
아무리 넓혀도 "면 위에 있어야 한다"는 요구를 만족시키지 못하고, 좁히면 아무것도 안 뽑힌다.
**Type 2는 m=1이어도 rejection이 아니라 투영으로 가야 한다.**

### 2.1 (해결됨) additional DOE의 증폭 상한

원래 additional DOE도 증폭 상한이 구조적으로 막혀 있었다:

```python
# 변경 전
r_used = max(crate_hat, plan_filter_r_floor)   # floor = 0.02
inv    = ceil(1 / r_used)                      # 따라서 최대 50
n_gen  = ceil(target * 1.2 * inv * boost)      # 최대 50 x 1.2 x 8 = 480배
```

`crate_hat`이 `plan_filter_r_floor=0.02`에서 잘려 실제 수율이 0.04%여도 2%로 기록되었고,
폭주를 막으려는 floor가 등식에서는 과소생성을 보장했다. 최대 480배라 m=2(2,500배 필요)에서 실패했다.

**이 부분은 구현으로 해결되었다.** 등식이 있을 때만 통과율 하한을 `1e-5`로 낮추고
(`plan_filter_r_floor_equality`), 폭주 방지는 후보 개수 절대 상한
(`plan_generation_max = 2,000,000`)으로 옮겼다. 초기 DOE의 probe 생성량도 매 시도마다
관측 통과율을 반영해 자기교정하도록 바꿨다. 등식이 0개면 모든 경로가 기존과 동일하다.

따라서 **additional DOE는 m <= 2를 rejection으로 처리한다.**

### 2.2 상한 완화가 커버하는 범위는 Type 1뿐이다

절대 상한 200만 개 안에서 m=2(2,500배)는 해결되지만 m=3(125,000배)은 걸린다.
`expr` 평가 비용 자체도 m=3에서 스테이지당 수백만 회가 되어 실용 한계에 닿는다.

| | m=1 | m=2 | m>=3 |
|---|---|---|---|
| **Type 1** (밴드) | rejection (구현됨) | rejection (구현됨) | 상한 도달. 유저가 밴드를 넓히면 해결 |
| **Type 2** (구조적) | **투영** | **투영** | **투영** |

**중요: Type 2에는 m 임계가 없다.** 등식 1개여도 투영으로 가야 한다.
밴드로 다루는 것 자체가 잘못된 처리이기 때문이다.

이전 판에서 "투영은 m>=3에서 필요하다"고 적었던 것은 Type 1/Type 2를 구분하기 전의
서술이며 **폐기한다.** m 임계는 Type 1(밴드 rejection)에만 해당한다.

### 2.3 plain DOE의 현행 전면 차단은 rejection 때문이다

plain DOE도 상한만 풀면 m=1은 기계적으로 돌아간다(2% 수율에 필요 50배, 현재 약 120배).
그럼에도 막는 이유는 **생성 능력이 아니라 표본 품질**이다.

통과율 2%면 LHS 점 50개 중 1개만 살아남는다. 살아남은 점들은 고르게 퍼져 있지 않다 —
매니폴드가 LHS 격자를 우연히 지나가는 자리에만 있다. **rejection 생존 표본은 층화를 잃는다.**

여기서 두 도구가 갈린다.

| | rejection 이후 |
|---|---|
| additional DOE | 이후 적응 단계가 대리모델/margin/local 정보로 **커버리지를 복구**한다 |
| plain DOE | one-shot이라 **복구할 기회가 없다.** 망가진 표본이 곧 최종 데이터셋이다 |

즉 현행 plain/additional의 갈라짐은 자의적 불일치가 아니라 **복구 능력의 차이에 근거한 선**이다.
`doe_orchestrator.py`의 `_has_equality_constraints` docstring에 같은 내용을 기록해 두었다.
"돌아가는데 왜 막았지"라는 이유로 그 가드를 풀지 말 것.

**단 이 근거는 rejection에만 해당한다.** 투영은 rejection이 아니므로 층화 손실이
같은 방식으로 발생하지 않고, 6절의 오버샘플 + maximin으로 상당 부분 회복된다.
따라서 **투영이 구현되면 plain DOE의 Type 2 차단은 해제 대상**이다.
Type 1(밴드 rejection)에 대한 차단은 그대로 유지한다.

---

핵심 전환:

> 밴드에 도달하는 방법을 **"무작위로 던져서 맞기를 기다린다"**에서
> **"계산해서 걸어간다"**로 바꾼다.

**eps 밴드 자체는 그대로 유지한다.** eps는 feasibility 판정 기준이고,
투영의 수렴 판정도 `|h - L| <= eps`를 쓴다. eps가 없으면 투영이 성립하지 않는다.
대체되는 것은 eps가 아니라 rejection sampling이며, `pre_equality_boost`는 불필요해진다.

## 3. 해법 — 매니폴드 투영

### 3.1 문제 정의

LHS로 뽑은 점 `x0`가 등식을 위반할 때, 가장 가까운 매니폴드 위의 점을 찾는다.

```
min ||x - x0||^2   s.t.  h(x) = L,   lb <= x <= ub
```

여기서 `h: R^p -> R^m` (등식 m개), `L`은 limit 벡터.

### 3.2 최소노름 Newton 보정

잔차를 정의한다.

```
r = h(x) - L                            (m,)
```

1차 선형화:

```
h(x + dx) ~= h(x) + J dx = L
=> J dx = -r                            J = dh/dx,  (m x p)
```

`m < p`이므로 이는 **미지수 p개, 방정식 m개인 부정(underdetermined) 계**이고
해가 무한히 많다. 그중 `||dx||`가 최소인 해를 고른다 (= 점을 가장 적게 움직이는 보정).

라그랑주 승수로 풀면 Moore-Penrose 유사역행렬 해가 나온다:

```
dx = -J^T (J J^T)^-1 r
```

`J`의 rank가 부족할 때를 대비해 Levenberg 감쇠를 넣는다:

```
dx = -J^T (J J^T + lambda I)^-1 r       lambda: 작은 감쇠항
```

**이 한 식이 m개 등식을 동시에 처리한다.** h1을 맞추다 h2를 깨는 순차 방식이 아니다.
커플링은 `J J^T`의 비대각 성분에 그대로 담긴다:

```
J J^T = [ <grad h1, grad h1>   <grad h1, grad h2> ]
        [ <grad h2, grad h1>   <grad h2, grad h2> ]
```

비대각 `<grad h1, grad h2>`가 곧 "두 제약이 얼마나 간섭하는가"이고,
역행렬을 취하는 것이 그 간섭을 풀어내는 것이다.
**따라서 여러 등식이 같은 변수를 공유해도 문제되지 않는다. 그것이 정상 케이스다.**

### 3.3 야코비안 — 유한차분

`expr`은 임의의 Python 식이므로 해석적 미분을 쓸 수 없다. 전진차분으로 구한다.

```
J[i][j] ~= ( h_i(x + delta * e_j) - h_i(x) ) / delta
delta    = delta_rel * max(|x_j|, 1)          delta_rel ~ 1e-6
```

비용: 반복당 `m * (p + 1)`회의 `expr` 평가. `expr` 평가는 `eval()` 한 번이라
마이크로초 단위이므로 무시 가능하다.

### 3.4 박스 제약과 선탐색

Newton 스텝은 박스를 벗어날 수 있고, clip하면 `h(x) = L`이 다시 깨진다.
순진하게 "Newton -> clip" 반복하면 발산할 수 있으므로 **잔차 감소를 강제한다.**

```
alpha = 1
repeat up to 5 times:
    x_new = clip(x + alpha * dx, lb, ub)
    if ||h(x_new) - L|| < ||h(x) - L||:  accept
    alpha = alpha / 2
```

이렇게 하면 박스 안에서 단조 수렴이 보장된다.

### 3.5 전체 알고리즘

```
def project_to_manifold(x0, h, L, eps, lb, ub, max_iter=8):
    x = clip(x0, lb, ub)

    for _ in range(max_iter):
        r = h(x) - L
        if all(abs(r) <= eps):
            return x, True                        # 수렴

        J  = finite_diff_jacobian(h, x)           # m*(p+1) expr 평가
        dx = -J.T @ solve(J @ J.T + lam*I, r)     # 최소노름 + 감쇠

        alpha = 1.0
        for _ in range(5):                        # 선탐색
            x_new = clip(x + alpha*dx, lb, ub)
            if norm(h(x_new) - L) < norm(r):
                break
            alpha *= 0.5
        else:
            return x, False                       # 진전 없음 -> 이 점 포기

        x = x_new

    return x, all(abs(h(x) - L) <= eps)
```

### 3.6 수렴 특성과 비용

- 매끄러운 `h`: Gauss-Newton이므로 매니폴드 근처에서 **2차 수렴**. 보통 3~5회.
- **등식이 모두 선형이면 `J`가 상수이고 1회 반복에 정확히 수렴한다.**
  이 경우 `J^T (J J^T)^-1`를 한 번 계산해 모든 점에 재사용할 수 있다.
- 점당 총 `expr` 평가: 대략 50~150회.

비용이 `m`에 **선형**이라는 것이 핵심이다. rejection은 `m`에 지수적이다.

| m | rejection (점당) | 투영 (점당) |
|---|---|---|
| 1 | ~50 | ~50 |
| 2 | ~2,500 | ~100 |
| 3 | ~125,000 | ~150 |

## 4. 등식 + 부등식 혼합

투영은 **등식만** 맞춘다. 투영된 점이 부등식을 위반할 수 있다.

**처리 순서: 투영 먼저, 부등식 필터 나중.**

```
LHS 생성
  -> 등식 투영            (매니폴드 위로 이동)
  -> 부등식 rejection 필터 (기존 로직 그대로)
  -> 통과한 점만 사용
```

순서를 뒤집으면 안 된다. 부등식을 먼저 걸러도 투영이 점을 움직이므로
그 부등식을 다시 깰 수 있다.

**수율 분석**: 투영 단계 수율은 ~100%이므로 최종 수율은 **부등식 수율만큼**이다.
즉 등식이 있든 없든 부등식 rejection의 부담은 동일하며,
이는 현재 plain DOE가 이미 감당하고 있는 수준이다.

따라서 **등식 + 부등식 혼합도 풀린다.** 등식이 수율을 추가로 깎지 않는다.

## 5. 실패 조건

### 5.1 개별 점 실패 — 오버샘플로 흡수

| 조건 | 원인 | 대응 |
|---|---|---|
| `grad h ~= 0` | 그 점에서 `h`가 국소 극값 (`x1^2 = 0`의 x1=0 근처) | 감쇠 적용, 안 되면 해당 점 포기 |
| 비선형 + 먼 시작점 | 수렴 실패 | 해당 점 포기 |

전량 실패가 아니므로 오버샘플(6절)로 흡수된다.

### 5.2 전량 실패 — 문제 정의 오류

| 조건 | 예시 |
|---|---|
| 등식끼리 모순 | `x1+x2=1` 이면서 `x1+x2=2` |
| 매니폴드가 박스 밖 | 등식은 만족 가능하나 `lb~ub` 안에서는 불가능 |

**이는 방법의 한계가 아니라 답이 존재하지 않는 문제다.**
어떤 방법으로도 풀 수 없다.

다만 **진단 품질이 개선된다.** 현재는 이런 경우도
`FAILED_FILTER_MIN: 12000개 생성해서 3개 찾음`으로 뭉뚱그려지는데,
투영이 전량 실패하면 **"이 제약은 주어진 bounds 안에서 만족 불가능"**을
확정적으로 보고할 수 있다.

### 5.3 사전 검증 — 투영 시도 전에 막을 것

현재 이 검사가 없다. 추가해야 한다.

**독립 등식 수 < 설계변수 수**

정확한 기준은 등식의 raw 개수 `m`이 아니라 **`rank(J)`**이다.
중복 등식은 자유도를 깎지 않기 때문이다.

```
x1 + x2 = 1
2x1 + 2x2 = 2      <- 같은 식. m=2 이지만 rank(J)=1
```

설계변수 2개에 위처럼 쓰면 겉보기엔 `m = p`라 막힐 것 같지만
실제 자유도는 1이 남으므로 **정상 동작한다.**

판정:

```
rank(J) >= p        -> 자유도 0. 해가 점 하나이거나 공집합. 거부
p - rank(J) < 2     -> 자유도 1. DOE로 탐색할 공간이 거의 없음. 경고
rank(J) < m         -> 중복 또는 모순.
                       잔차가 0으로 수렴 가능하면 중복(정상 동작),
                       불가능하면 모순(거부)
```

`rank(J)`는 SVD로 구하며, 비선형이면 `J`가 위치에 따라 변하므로
여러 샘플점에서 확인한다.

**부등식은 이 검사와 무관하다.** 부등식은 영역을 깎을 뿐 자유도를 없애지 않으므로
설계변수 2개에 부등식 100개여도 문제없다.

## 6. LHS 균등 배치 보존

투영의 유일한 실질적 대가는 **점들이 매니폴드가 휘는 곳에 뭉치는 것**이다.
plain DOE는 one-shot이라 만회 기회가 없으므로 이 대가가 특히 아프다.

**대응: 오버샘플 + maximin 부분선택**

```
1. n_samples * s 개를 LHS로 생성        (s = 4~5)
2. 전부 투영. 실패한 점은 버림
3. 남은 것 중 n_samples 개를
   최소 쌍거리가 최대가 되도록 탐욕 선택
```

투영이 점을 뭉치게 만들어도 뭉친 곳에서는 하나만 선택되므로
최종 `n_samples` 개는 고르게 퍼진다. Voronoi나 반복 완화는 필요 없다.

이 오버샘플은 5.1의 개별 점 실패도 함께 흡수한다.

비용 예시 (n=90, s=5, p=9, m=1): 투영 450회 x ~50 expr 평가 = 22,500회,
maximin 탐욕 선택 O(450 x 90). **초 단위이며 비용은 제약이 아니다.**

## 7. 남은 설계 항목 (구현 시 결정)

- **코너 샘플링**: 박스 코너는 거의 확실히 매니폴드 위에 없다. 투영하면 코너가 아니게 되어
  "경계를 덮는다"는 목적이 사라진다. 매니폴드와 박스면의 교집합을 뽑는 별도 로직이 필요한지 판단.
- **baseline**: `force_baseline_initial`로 넣는 baseline이 등식을 만족하지 않으면
  투영되어 baseline이 아니게 된다. 그대로 둘지, 투영할지, 경고만 할지 결정.
- **선형 등식 특수화**: `J`가 상수임을 감지해 `J^T (J J^T)^-1`를 사전 계산·재사용.
  더 나아가 영공간 좌표계에서 직접 LHS를 돌리면 균등 배치가 완벽히 보존되므로
  6절의 오버샘플 자체가 불필요해진다. 선형 케이스 전용 최적화로 후순위.
- **차단 정책 해제**: 현재 `doe_orchestrator.py:339`의 `_has_equality_constraints`가
  scope 무관하게 `==` 전체를 차단한다. 투영 도입 시 **pre 등식은 허용, post 등식은 차단**으로
  변경해야 한다.

## 8. 적용 범위 (구현 시)

투영은 "DOE 후보 생성"이 아니라 **"pre Type 2 등식에 대해 후보를 생성하는 모든 곳"**에 들어간다.

| 위치 | 현재 | 도입 후 |
|---|---|---|
| plain DOE 샘플링 | 등식 전면 차단 | Type 2는 투영, Type 1 밴드는 차단 유지 (2.3) |
| additional DOE 후보 생성 | rejection + `2^m` 증폭 | Type 2는 투영, `pre_equality_boost` 제거 |
| Optimizer Focus0 / Focus3 후보 풀 | soft 페널티 (`pre_equality_penalty.py`) | 투영 (검토) |

Optimizer를 빼면 **DOE는 면 위에서 뽑는데 Optimizer는 벗어난 점을 제안하는 불일치**가 생긴다.
Optimizer의 pre 제약도 싼 `expr`이므로 비용 문제는 없으며,
투영은 위반을 허용하고 벌점만 주는 soft 페널티보다 엄밀히 우수하다.

### 8.1 additional DOE에서의 삽입 지점 3곳

**① `_filter_by_constraints`** — 후보 필터 7곳이 전부 이 함수를 거치므로 여기 한 곳이면 된다.

```
X 입력
 -> Type 2 등식으로 투영          (점이 면 위로 이동)
 -> 수렴 실패한 점 제거
 -> 나머지로 rejection 필터        (부등식 + Type 1 밴드)
 -> 반환
```

**순서가 중요하다. 투영 먼저, 필터 나중.** 투영이 점을 움직이므로 반대로 하면
통과시킨 점이 투영으로 다시 밖으로 나갈 수 있다.

주의: 이 함수는 네 번째 반환값으로 `mask`를 주고 `:1886`(local 후보)이 그 mask로
후보와 앵커를 대응시킨다. 투영은 점을 이동시키지 제거하지 않으므로 대응은 유지되지만
구현 시 확인이 필요하다.

**② LocalSampler** — 지금은 boolean 오라클(`pre_feasible_fn`)을 받아 rejection 루프를 도는데,
Type 2 등식에서는 아무것도 통과시키지 못하고 폴백으로 떨어진다.
**투영 함수를 받도록 시그니처를 바꾼다.**

```
앵커 (면 위)  ->  가우시안 섭동 (면 밖)  ->  투영 (면으로 복귀)
= 면을 따라 움직이는 local search
```

개념적으로 여기가 가장 자연스럽다. 부수 효과로 `local_constraint_retry`
(반경 0.75배 축소 재시도)가 불필요해진다.

**③ 획득함수 (`anchor_refiner`)** — L-BFGS-B가 pre 제약을 `1e9` 페널티로 다루는데
Type 2 등식이면 면도날 골짜기라 절대 못 찾는다. **결과를 사후 투영**하고,
Type 2에 대한 `1e9` 페널티는 제거한다.

### 8.2 함께 고쳐야 할 파생 신호 2개 — 이쪽이 본체다

투영 함수 삽입은 1곳이지만, 아래 둘을 빠뜨리면 **에러 없이 선택 품질만 나빠진다.**
규칙은 하나로 정리된다.

> **`margin`과 `constraint_rate_hat`은 rejection으로 처리되는 제약만으로 계산한다.**
> 투영으로 처리되는 Type 2 등식은 양쪽 모두에서 제외한다.

**margin** — Type 2를 투영하면 모든 점이 `margin ~= eps`로 같아진다. `margin`은 pre 제약의
최솟값이고 eps는 보통 부등식 margin보다 작으므로, 부등식이 섞여 있어도 전체가 뭉갠다.
그러면 `argsort(margins)`가 인덱스 순서로 퇴화해
**exec 예산의 30%(margin bucket)가 임의 선택**이 된다.
투영된 등식은 정의상 모든 점이 경계 위에 있으므로 거리 개념 자체가 없다.

Type 1 밴드와 부등식은 **포함한다.** 밴드 안에서 얼마나 여유가 있는지는 여전히 의미가 있다.

**constraint_rate_hat** — 투영 후 Type 2의 통과율은 ~1.0이 된다. 이 값이 후보 증폭 계산
(1.0이 정답)과 고제약 분기 판정(1.0이면 "무제약"으로 오판)에 동시에 쓰인다.
rejection 대상만으로 통과율을 계산하면 둘 다 맞는다.

### 8.3 예산 영향 없음

투영은 `expr`만 평가하고 CAE를 부르지 않는다. `ExecutionBudget`은 CAE 호출만 세므로
투영 반복 횟수와 무관하다.

## 9. 구현 상태

### 확정된 정책 (목표 상태)

| | Type 1 (eps 있음) | Type 2 (eps 없음) |
|---|---|---|
| pre | 밴드 rejection | **투영** |
| post | CAE 후 라벨링 | **정확 일치로 라벨링 + feasible 부족 시 경고** |

### 현재 코드 상태

| 항목 | 상태 |
|---|---|
| **Type 1 / Type 2 구분** | **미구현.** 지금은 eps가 없으면 자동으로 `limit`의 2%를 채운다 |
| **자동 eps 제거** (`eps_ratio`/`eps_min`) | **미구현.** `constraint_filter.py:151-157` |
| **post feasible 부족 경고** | **미구현.** 지금은 조용히 통과하고 Modeler가 `<10 feasible`로 죽는다 |
| **투영** | **미구현** |
| plain DOE 등식 차단 | 구현됨 (`_has_equality_constraints`, scope 무관 전면 차단) |
| additional DOE 후보 생성 상한 완화 | **구현됨** (`plan_filter_r_floor_equality`, `plan_generation_max`) |

**즉 지금은 Type 1/Type 2가 구분되지 않으므로, Type 2 등식이 들어오면
자동 eps로 밴드가 되어 rejection으로 처리된다.** 이것이 이 문서가 고치려는 상태다.

### 구현 순서

1. **자동 eps 제거 + Type 1/2 구분** — `validate_constraint_defs`.
   eps가 없으면 pre는 투영 대상으로, post는 정확 일치로 표시한다.
   가장 작고, 나머지 전부의 선행 조건이다. 기존 테스트 2개 수정 필요
   (`test_constraint_filter.py`가 자동 eps 동작을 검증하고 있다)
2. **post feasible 부족 경고** — 등식/부등식 공통. 1과 독립적으로 진행 가능하며,
   빡센 post 부등식의 조용한 실패도 함께 잡는다
3. **투영 함수** — 순수 함수. 어디에도 붙이지 않고 합성 테스트만
4. **margin / constraint_rate_hat 재정의** (8.2) — Type 2가 없으면 무영향이라 선행 가능
5. **투영 연결** — `_filter_by_constraints`, LocalSampler, 획득함수 (8.1)
6. **`pre_equality_boost` 제거**, plain DOE의 Type 2 차단 해제

### 벤치마크 영향

벤치마크 4문제(cantilever_beam, rosenbrock, goldstein_price, six_hump_camel)에는
등식 제약이 하나도 없다(cantilever의 pre 부등식 2개가 전부).
따라서 위 구현과 이 설계는 110-run 벤치마크 점수와 무관하다.
