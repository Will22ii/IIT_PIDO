### doe_pre_equality_projection.md

| | |
|---|---|
| 상태 | **plain DOE 투영 구현됨. additional DOE 미구현** |
| 핵심 | 등식은 두 종류이고 **eps의 유무**가 이를 가른다 |

**Type 1 (eps 있음)** — 공차 있는 목표값(고유진동수 50Hz 등). 밴드 rejection. **현행으로 동작.**
**Type 2 (eps 없음)** — 구조적 등식(기하 폐합, 비율 고정). 설계공간의 정의. **투영 필요.**

| | Type 1 | Type 2 |
|---|---|---|
| pre | 밴드 rejection (동작) | **투영** (미구현) |
| post | CAE 후 라벨링 (동작) | 정확 일치 라벨링 + **feasible 부족 시 경고** (미구현) |

post Type 2는 **이산 출력**(`n_modes == 3` 등)에서 실재하지만 투영이 필요 없다.
이산 출력의 역상은 얇은 면이 아니라 부피를 가진 영역이라 rejection 통과율이 정상이기 때문이다.
반대로 연속 출력에 대한 정확 등식은 물리적·수치적으로 의미가 없으므로,
feasible이 0으로 나오면 경고해서 유저가 공차를 명시하도록 유도한다.

**지금 코드는 Type 1/2를 구분하지 못한다.** eps가 없으면 자동으로 `limit`의 2%를 채워
Type 2를 Type 1인 척 처리한다(`constraint_filter.py:151-157`). `limit=0`이면 그 계산에
근거조차 없어진다. **자동 eps 제거가 나머지 전부의 선행 조건이다** (문서 1절, 9절 구현 순서).

이미 구현된 것: additional DOE의 후보 생성 상한 완화
(`plan_filter_r_floor_equality`, `plan_generation_max`). 이는 **Type 1 밴드에만 해당**하며
Type 2에는 m 임계가 없다 — 등식 1개여도 투영으로 가야 한다 (문서 2.2).

투영을 재매개화 대신 택한 이유는 유저 입력의 일반성이다. 재매개화는 식을 풀어야 하므로
초월식에서 실패하고 다항식에서 가지가 갈라져 설계공간 절반을 조용히 버린다.
투영은 식을 블랙박스로 다루고 가장 가까운 점으로 가므로 두 문제가 모두 없다.
대신 차원이 줄지 않아 하류에 다중공선성이 남는다 (문서 8절).

### additional_doe_linear_equality_elimination.md

| | |
|---|---|
| 상태 | **설계만. 미구현. 우선순위 낮음(보류)** |
| 핵심 | 등식을 풀어 변수를 소거하면 additional DOE를 **수정 없이** 쓸 수 있다 |

plain DOE는 투영으로 Type 2를 풀지만 additional DOE는 못 푼다. 투영을 그대로 얹으면
통과율이 항상 100%가 되어 Gate 판정이 무의미해진다 — additional은 **정의역이 박스**라는
전제 위에 지어져 있고 등식이 그 전제를 깨기 때문이다.

해법은 additional을 고치는 것이 아니라 전제를 되돌리는 것이다. 자유도만큼의 좌표에서 보면
그 면은 다시 박스다. 축소 방법으로 **영공간 좌표계와 변수 소거를 비교했고 소거를 택했다** —
통과율이 더 높고(66.7% vs 56.2%) 무엇보다 **변수 이름이 살아남아** Modeler FS와
Explorer bounds, debug 로그가 그대로 동작한다. 소거 변수 선택은 피벗팅 QR이 자동으로 한다.

선형 등식에만 적용된다. 비선형 Type 2는 plain DOE의 투영으로 보낸다.

## 미확정 항목

**DOE post feasibility 분류기의 검증 부재.** additional DOE는 post 제약이 있을 때
`(X, feasible)`로 XGBClassifier를 학습해 후보 점수에 페널티로 반영한다
(`_fit_post_feasibility_model`, `_make_penalized_models`). 문제는 **이 모델이 검증되지 않는다**는 것이다.

- 정확도도 CV 점수도 held-out 검사도 없다. 진단에는 `post_model_active` 불리언만 나온다
- 목적함수 대리모델은 Gate1(top-k 안정성)/Gate2(불확실성)의 검사를 받지만
  **이 분류기는 그 관문을 우회한다.** 검증 안 된 모델이 어떤 점을 CAE에 보낼지 결정한다
- 결과가 나빠도 "DOE가 탐색을 못한 건지 분류기가 잘못 이끈 건지" 구분할 수 없다

선택지: 최소(진단에 정확도·표본 수 노출) / 중간(Gate 규율 적용) / 최대(제거하고 라벨만 유지).

등식과 무관한 별개 문제이며, 벤치마크 4문제에 post 제약이 없어 현재는 발동하지 않는다.
